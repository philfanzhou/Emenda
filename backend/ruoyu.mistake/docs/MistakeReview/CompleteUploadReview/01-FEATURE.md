# 完成上传审核 (CompleteUploadReview)

## 功能名称和一句话概括

完成上传审核 — 在上传记录中所有错题审核完毕后执行最终处理：将已确认错题的 OSS 图片从临时上传目录迁移到正式错题目录，清理上传记录中的图片引用，并为已驳回的错题跳过迁移。

## 核心用户故事

1. **老师完成审核批次**：作为老师，当我对某个上传记录中的所有错题完成逐条审核后，调用"完成审核"来触发最终的图片迁移和清理操作，让已确认的错题正式生效。

2. **系统自动图片迁移**：作为系统，我需要将已确认错题的图片从 `uploads/` 临时目录拷贝到 `mistakes/` 正式目录并删除原文件，确保 OSS 存储结构与错题状态保持一致。

3. **系统清理上传记录**：作为系统，在完成图片迁移后，我需要调用 Student 服务的 `RemoveImagesFromRecord` 接口清理上传记录中的图片引用，释放上传记录存储空间。

## 关键验收条件摘要

- AC-1：上传记录中所有错题审核完毕（无 PendingReview 状态）后才能执行完成操作，否则返回失败。
- AC-2：已确认（Confirmed）的错题：OSS 图片从 `uploads/{path}` 拷贝到 `mistakes/{path}`，删除原文件，更新 `source_regions` 路径。
- AC-3：已驳回（Rejected）的错题：跳过图片迁移，仅从上传记录中移除图片引用。
- AC-4：单个图片迁移失败不阻塞整个流程，记录 Error 日志后继续处理后续图片。
- AC-5：收集所有图片路径后调用 Student 服务的 `RemoveImagesFromRecord` 清理上传记录。
- AC-6：路径映射缓存：相同旧路径的多次引用只迁移一次，后续直接使用已缓存的 newPath。

## 明确列出"范围外"（不做什么）

- 不处理审核未完成的上传记录（应在前端提示用户先完成所有审核）。
- 不自动重试失败的图片迁移（由运维或手动触发重试）。
- 不提供回滚已迁移图片的能力。
- 不处理错误图片路径（非 `uploads/` 前缀的路径跳过迁移）。
