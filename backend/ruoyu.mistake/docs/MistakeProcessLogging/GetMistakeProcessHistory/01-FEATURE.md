# 错题处理历史查询 (GetMistakeProcessHistory)

## 功能名称和一句话概括

错题处理历史查询 — 根据错题条目 ID 查询该条目的完整处理日志列表，包含每条日志的操作类型、详情描述和时间戳，通过 gRPC 暴露查询接口。

## 核心用户故事

1. **教师查看错题处理历史**：作为教师，我希望通过一条错题的 ID 查看该错题从创建到当前的全部处理记录（创建 → 分析 → 审核 → 练习 → 掌握），了解错题的完整生命周期。

2. **管理员审计操作日志**：作为管理员，在审核错题管理质量时，我需要查看某条错题的处理日志列表，确认每一步操作都有记录且时间顺序正确。

## 关键验收条件摘要

- AC-1：传入合法的错题条目 ID 后，返回该条目下所有 ProcessLogDto 的列表，每个 DTO 包含 `id`、`mistake_item_id`、`action`、`details`、`created_at`。
- AC-2：当错题条目无任何处理日志时，返回空列表。
- AC-3：返回的日志按 `created_at` 升序排列（由仓储实现保证）。
- AC-4：`id` 参数必须为合法 GUID 格式。

## 明确列出"范围外"（不做什么）

- 不实现日志的分页查询（当前一次性返回全部日志）。
- 不实现按时间范围或操作类型筛选日志。
- 不验证错题条目 ID 是否真实存在（由仓储层自然返回空列表）。
- 不实现日志的聚合统计（如各操作类型计数）。
- 不实现日志的导出功能。
