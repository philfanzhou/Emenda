需求确认稿 · V2

错题图片自动识别、
解题判错与可追溯纠偏

上传一张或多张学习照片后，系统先识别版面和题目关系，再让 AI 解题并比对学生作答，区分正确、错误和无法判断。确认是错题后生成题图和待审核记录；原图始终保留，后续可以重新调整。

本稿已纳入两个新增要求：版面分析不能代替 AI 判错；题目关系同时支持“一图多题”和“多图一题”。本稿用于确认范围，不代表功能已经开发完成。

01 / CONCLUSION

先组题、再判错，原图可追溯

真正需要交付的不是单独的“AI 裁图”，而是一条可追溯的判断链路：原图、题目分组、学生作答、AI 解题、对错结论、裁剪版本和错题记录之间始终能够互相找到。

01

组织题目与判断对错

同时支持一图多题和多图一题；让 AI 解题、读取学生作答，记录判断依据。

02

原图作为事实来源

原始图片不覆盖、不删除。所有裁剪结果都能追溯到原图和具体区域。

03

支持裁剪与判定纠偏

从原图调整区域、分组或对错结论；保存新版本，不丢失审核和练习历史。

Recommended scope

建议采用“版面分析 + 题目组织 + AI 解题比对”的组合。版面分析负责找区域和题目关系，AI 负责给出参考解答并比对学生作答；只有有证据判定为错误的题目进入错题候选，无法判断的结果进入人工确认。

02 / SCOPE

建议范围与边界

需求项建议本期定义，待确认建议排除的内容
输入用户主动提交一张或多张学习照片；可以包含一题、多题或同一题的多个页面。不默认把整套试卷中的所有题都当成错题。
版面与题目关系识别题干、选项、配图、公式、小问，并建立“一图多题”和“多图一题”的关系。不把每个检测框直接当成一条题目或一条错题。
解题与判错AI 读取题目和学生作答，生成参考解答并输出正确、错误、无法判断三态。不把一次模型输出当作绝对正确，不跳过证据和审核。
自动入库有证据判定为错误的题目生成题图并创建待审核错题。正确题不进入错题库；无法判断的题不静默入库。
原图与纠偏原图作为不可变来源，裁剪、判定和人工调整均保留版本。不覆盖原图，不从旧裁剪图继续裁剪。
A版面分析不是判错

当前 StructaDoc 布局接口提供候选区域；检测顺序不保证题目阅读顺序，对错仍需独立判断。

B题目关系需要显式建模

一张图可以有多道题，多张图也可以共同组成一道题，不能只用单图单题假设。

C判错必须保留证据

保存题目、学生作答、参考解答和判断依据，正确、错误、无法判断三态分别处理。

D答疑和错题入库分开

可以复用问答的图片预处理和多图输入，但聊天回答本身不能直接变成错题事实。

03 / FLOW

业务流程

AI 负责理解题目、读取学生作答、给出参考解答并进行比对；服务端负责校验区域、保存原图、生成题图、记录证据和执行入库规则。这样可以避免模型重绘题目，也避免把版面区域误当成错题。

判断结果分为正确、错误、无法判断。只有错误题进入错题候选；人工纠偏始终回到原图，不修改历史事实。

04 / SOLUTION

推荐技术方案

LAYOUT

版面分析先找结构，不负责判错

  • 当前 StructaDoc 的 layout 接口只返回区域、坐标和布局元数据，不返回识别内容或对错结论。
  • 其后端配置为 MinerU Cloud，在线调用不要求这台笔记本提供本地 GPU。
  • 题目顺序、题干、选项、配图和作答区域需要在后续组织阶段合并。
  • 空区域不等于没有题；异常和无法组织的结果进入人工确认，不伪造成功。
QUESTION GRAPH

同时支持一图多题与多图一题

  • 一张图片可拆出多个题目组，每组包含自己的题干、作答和必要配图。
  • 多张图片可归并为同一道题，保留来源图片、区域顺序和跨页关系。
  • 每道题使用稳定的题目组身份；公共题干可被多题引用，重复照片不重复建题。
  • 裁剪结果从原图和区域集合生成，旧版本继续可追溯。
SOLVE & JUDGE

AI 解题后再比对学生作答

  • 向模型同时提供完整题目、学生作答和必要上下文，要求输出参考答案、解题过程和判断依据。
  • 结果固定分为正确、错误、无法判断，不能用“有模型回答”代替判定成功。
  • 可信参考答案明确时可做确定性比对；模型生成的解答仍需验证，主观题、模糊手写或材料不足可返回无法判断。
  • 只有错误且证据完整的题目自动创建待审核错题，判断结果和输入快照一起保存。
TUTORING BOUNDARY

复用问答能力，但不混淆业务事实

  • 优先让错题上传和答疑共用 AI Tutor 的模型调用、识题与题目组织能力，不在 Emenda 复制第二套解题逻辑。
  • 答疑会话的回答是辅导内容；错题判定需要独立的来源、证据和入库任务。
  • 学生明确要求“讲这道题”不等于学生做错；需要实际作答和可核对证据。
  • 模型、配额、超时和失败状态由配置和任务层管理，不把免费额度当作产品保证。
复用现有能力当前情况本次补齐
图片存储独立上传已将图片存入对象存储，并进行字节校验。把上传对象明确为不可变原图来源。
版面检测已有 StructaDoc 客户端、作业持久化和归一化坐标转换。接入独立上传来源，并在布局结果之后增加题目组织和判错。
问答能力已有 AI Tutor 的识题、解题、图片准备和多图输入边界。复用调用能力，但新增独立的判错证据和错题入库语义。
错题入库当前默认按整张图片创建错题区域。基于题目组、学生作答和错误证据生成派生图片及待审核错题。
来源保护受管来源的区域事实不能被普通更新接口随意改写。用题目组、判断快照和提取版本表达变化，不覆盖历史。

本地问答链路已有多图聊天、裁剪准备和会话错题证据模型，但既有结构化识题/解题接口仍按单图契约。多图组题、批量判错和独立版 Emenda 的服务间调用仍需扩展，不能把“支持多图聊天”当作已完成本需求。

Environment fact checked

已只读核对笔记本样例：StructaDoc 0.1.14-rc.3 容器运行且健康，布局后端配置为 mineru-cloud；健康检查和 OpenAPI 读取均返回 200。未提交真实图片推理，不能据此断言云端额度、模型调用或判错质量已经验收。

共用边界建议归属约束
布局检测StructaDoc 统一调用 MinerU Cloud，答疑和错题上传按需消费。只复用检测能力；本接口不返回识别正文。视觉模型仍需读取原图或题目图。
题目理解、解题与判错AI Tutor 提供共用的版本化结构化能力；批量上传和答疑是两个调用入口。题目组含多图区域、学生作答、参考解答和证据；一次模型自报置信度不等于正确率。
裁剪复用现有图像解码和裁剪能力，统一坐标转换约定。布局坐标、答疑框选坐标不能直接混用；不得依赖只在聊天期间有效的临时裁剪授权。
业务记录AI Tutor 管会话；Emenda 管独立错题、原图引用、判断版本和审核练习。服务间使用独立调用契约，不共享数据库；已收录错题不依赖聊天历史继续存在。

实施顺序：先固定共用输入输出及来源身份，再打通组题、判错和自动收录，最后完成纠偏页面及真实样本验收。采用版本化异步入口，不静默改变现有同步上传接口；复用现有持久任务，无需新建队列或业务服务。

MinerU 官方文档区分需 Token 的精准解析 API 和免登录轻量 API，后者只返回 Markdown，不宜直接替代需要区域坐标的布局契约。官方描述每日高优先级额度及降优先级机制，不等于永久免费无限量；当前账号权限、额度和服务条款需在上线前核对。在线解析不需本机 GPU，但图片会发送到云端。依据：MinerU 官方 API 文档。

06 / ACCEPTANCE

验收标准

以下为拟定验收条件，尚未执行功能验收。应使用真实样本验证，不只检查接口返回成功。

1
自动提取结果可用于展示

题干、选项、必要配图和小问完整保留，相邻题目不被错误带入。

2
每张题图都能回溯

能够从错题找到当前裁剪版本、原图、区域框和生成时间。

3
人工纠偏不破坏历史

同一道题调整范围后，错题 ID 和已有历史不丢失；历史图片仍能定位到当时版本。

4
一图多题与多图一题均可验收

覆盖跨页、公共题干、题号重复、重复拍照、旋转和配图；同题不重复建题，不同题不误合并。

5
异常结果不被伪装成成功

AI、存储、裁剪或数据库失败时，原图保留，任务状态和失败原因可见。

6
重复请求与访问权限正确

同一请求重试不重复建题；仅授权用户可调取原图和保存纠偏，凭据不下发浏览器。

7
判错三态与学生作答可核对

用人工标注的正确、错误、未作答、模糊手写、缺材料和主观题样本验证；保留学生作答和参考解答，无法判断不自动建错题。

8
共用能力不改变两端既有约定

相同题目来源可被答疑和错题上传消费；独立调用不依赖临时聊天授权，聊天删除不删除已收录错题。

效果验证

准确率需要用真实样本测量

上线前用分学科、分题型人工标注样本，分别测量识别完整率、分组准确率、错题误收率与漏收率、无法判断比例、人工纠偏比例、处理耗时及单题成本。范围和门槛由项目经理确认，不能只用模型自报置信度验收。

07 / DECISION

请项目经理确认的事项

新增方向已纳入，以下规则仍需确认

  1. 适用学科与题型：明确首批支持哪些学科、年级和题型；整页多题纳入判错，但不自动扩展为整卷评分系统。
  2. 题目粒度：一图多题、多图一题均在范围内；请确认大题中的部分小问做错时，按小问收录还是整道大题收录。
  3. 判定依据：可提供的标准答案或评分规则优先；没有时由 AI 生成参考解答并比对。未作答、材料不足和看不清的题建议进入无法判断，不自动当错题。
  4. 自动收录：建议有实际错误证据的题自动创建待审核记录，正确题只保留处理结果；无法判断的题在待确认区处理。
  5. 共用方案：建议复用现有 StructaDoc 与 AI Tutor，扩展多图题目组和结构化判错契约，不在 Emenda 复制解题实现，也不把自由聊天文本直接入库。
  6. 人工纠偏：请确认教师、助教、学生哪些角色可改裁剪、分组和对错结论；已审核错题变更后建议重新审核，保留原有历史。
  7. 数据与上线：明确云端处理学生照片的范围、原图和历史版本保留规则、MinerU 账号额度、模型预算及真实样本验收门槛；范围确认后再估算排期。
